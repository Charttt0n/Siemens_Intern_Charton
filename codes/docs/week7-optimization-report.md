# Week 7 代码体积与启动时间优化报告

## 结果与比较对象

在同一轮性能摘要（`codes/logs/week7-benchmark-20261113-204522/summary.json`，状态 PASS）中，正式 Bootloader 的 text+data 从 29132 字节降至 27204 字节，减少 1928 字节，即 6.62%。对 128 KiB 已签名镜像，验证、加载至交接的固定 QEMU 模型中位耗时从 289.0 ms 降至 165.0 ms，减少 124.0 ms。安全检查与试运行保护仍由 `make verify-week7` 的 29 个分组和 93 个 Unity 用例回归。

本次时间指标是 QEMU 仿真比较量，不是真机毫秒性能或精确 Cortex-M7 周期。它只适合比较本工程在同一模型下的相对变化，不能用来承诺工业启动时限或板上最坏启动时间。

| 构建版本 | ELF | text | data | text+data | bss_including_stack |
|---|---|---|---|---|---|
| 基线，业务代码 `-Og` | `bootloader-week6.elf` | 29124 | 8 | 29132 | 41176 |
| 修复后调试，业务代码 `-Og` | `bootloader-week7-debug.elf` | 29712 | 8 | 29720 | 41176 |
| 正式优化，业务代码 `-Os` | `bootloader-week7.elf` | 27196 | 8 | 27204 | 41176 |

修复后的调试版较基线增加 588 字节；相同修复源码改用 `-Os` 后较调试版减少 2516 字节。对原基线的净减少是 1928 字节，不能把全部收益都归给单一改动。正式装载体积低于 64 KiB 代码区上限。本轮摘要给出的是包含栈预留的 `bss_including_stack`，不另宣称降低了 RAM 占用或测出了最大栈深度。

三个 ELF 的 SHA256（摘要记录）分别为：

- 基线 `f17676fc5e42c1de3935952d911f9c66420c2322853c584ddab607420aa8f050`
- 调试 `1f4085079b7349ac9113035de016ca9a255efc5db66b0e80017d189adc321ce9`
- 正式 `7cc412355e580ab17d72648ee47c8a821f8b6bb00fbe864601bad8bcf84a14cc`

## 测量方法

证据根目录为 `codes/logs/week7-benchmark-20261113-204522`。摘要写明测量模型为 QEMU icount shift=3，每条仿真指令 8 ns，TIMER0 按 25 MHz 计时。每种构建分别使用相同的演示 payload（3360 字节）和填充至 131072 字节的 payload。每组重复 3 次，报告中位数。

命令窗口固定 200 ms，只是双方相同的实验参数，产品默认窗口仍为 2500 ms；缩短窗口不计作算法或编译优化。摘要注明 Simulation only, no cycle-accurate hardware performance claim。

## 启动路径实测

下表数字均取自摘要中的 `median_verify_ms` 与 `median_total_ms`。三次样本在各组内一致。`verify` 对应验证、加载至交接；`total` 对应 main 至交接（其中 `before_ms` 均为 202.0006 ms，含初始化与 200 ms 窗口）。

| 镜像与版本 | 验证加载至交接（中位） | main 至交接（中位） |
|---|---|---|
| 演示 3360 字节，基线 | 36.0 ms | 238.0006 ms |
| 演示 3360 字节，修复调试版 | 33.0 ms | 235.0006 ms |
| 演示 3360 字节，正式优化版 | 31.0 ms | 233.0006 ms |
| 128 KiB，基线 | 289.0 ms | 491.0006 ms |
| 128 KiB，修复调试版 | 178.0 ms | 380.0006 ms |
| 128 KiB，正式优化版 | 165.0 ms | 367.0006 ms |

对 128 KiB 镜像，验证加载路径由 289.0 ms 降至 165.0 ms；含固定窗口的总路径由 491.0006 ms 降至 367.0006 ms。演示镜像的验证加载路径由 36.0 ms 降至 31.0 ms。固定 icount 使三次数据相同，说明本实验可复现，不表示获得真实硬件的统计置信区间。报告保留摘要中的小数位以便对账，不把小数位当作硬件准确度。

## 实现说明与复现

实现上，CRC32 改为 16 项半字节表（64 字节只读常量），并以独立逐位算法做宿主对照；镜像、元数据与签名升级回归仍走同一 CRC 接口。CMake 将业务优化参数显式传给公共配置函数，避免重复参数去重后使调试与正式目标实际使用同一组标志。构建选项、map 和 ELF SHA256 保留在本轮证据中。未在摘要之外补充未核对的多项式向量或段布局细节。

从 `codes/` 目录执行：

```sh
source scripts/env.sh
bash scripts/build-week7.sh
make benchmark-week7
make verify-week7
```

本报告所用体积与时间数字均来自上述性能摘要，对应最终验收构建中的三个对照 ELF，而不是另行重测的结果。

## 解释限制

优化版已通过本轮 93 个 Unity 用例和 29 个验收分组。调试与性能脚本使用的是 QEMU 自带 GDB remote stub，规划书要求的实体 OpenOCD/JTAG 链路尚未执行。当前结果不能证明真机 Flash 等待状态、Cache、总线争用、功耗、最坏启动时间或真实看门狗电气行为。测试密钥只是实验夹具，不可用于生产。本地通过不等于老师验收；本轮未提交或推送 Git。
